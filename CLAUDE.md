## What this is

Bus Koi (`বাস কই`) is a Flutter MVP for community-driven, temporary bus tracking in Dhaka. There is no
predefined bus database: a commuter waiting for a bus creates or joins a temporary "community" for that
bus name, and a commuter currently riding it can voluntarily share their live location with that
community. Communities and their data are meant to disappear once nobody needs them.

The full product spec (target users, screens, lifecycle rules, anti-abuse notes, explicit non-goals) is
in `prompt.md` at the repo root — read it before making product-behavior decisions; it is the source of
truth for *what* the app should do.

## Commands

- Install deps (also regenerates localization via `generate: true` + `l10n.yaml`): `flutter pub get`
- Regenerate localization manually: `flutter gen-l10n`
- Static analysis: `flutter analyze`
- Run all tests: `flutter test`
- Run a single test file: `flutter test test/widget_test.dart`
- List devices: `flutter devices`
- Run on a specific device: `flutter run -d <device-id>`

### JDK gotcha

Flutter defaults to the JDK bundled with Android Studio. If that JDK has been auto-updated to something
Gradle's Kotlin DSL script compiler can't parse yet (this has broken on JDK 25 against Gradle 8.14 with
`IllegalArgumentException: <version>` while compiling `build.gradle.kts`), both `flutter run` and
Android Studio's Run button fail near-instantly. Fix by pinning Flutter to a known-good JDK (17):

```
flutter config --jdk-dir="<path-to-a-jdk-17-install>"
```

This is a machine-local Flutter tool setting, not a project file — it doesn't need committing and won't
show up in `git status`.

## Architecture

Feature-based MVVM using `provider` for state management. The rule that matters: **only
`lib/features/community/data/community_repository.dart` talks to Firebase directly.** Everything above
it (view models, screens) works in terms of the plain model classes in `lib/shared/models/` — this is
what makes the backend swappable and keeps Firebase specifics out of the UI layer.

```
lib/
  core/
    constants/app_constants.dart   # every tunable (timeouts, TTLs, intervals) — nothing else hard-codes these
    theme/                         # AppTheme, light/dark
    routing/app_router.dart        # named routes: home, community, settings
    services/                      # IdentityService, LocationService, ConnectivityService
    utils/                         # NameNormalizer, RelativeTimeFormatter
    localization/gen/              # generated by `flutter gen-l10n` — gitignored, do not hand-edit
  features/
    home/presentation/             # search-to-create-or-join, live active-community list
    community/
      data/community_repository.dart   # the only Firebase Realtime Database touchpoint
      presentation/                    # map screen (demand, latest location, notify/supplier actions)
    settings/presentation/         # language switch, privacy/about copy
  shared/
    models/                        # Community, CommunityMember, LocationReport (plain Dart, no Firebase types)
  firebase_options.dart            # placeholder — run `flutterfire configure` for a real project
  l10n/app_en.arb, app_bn.arb      # source strings; localization gen output goes to core/localization/gen
```

### Backend: Firebase Realtime Database, no auth

The product spec (`prompt.md`) originally suggested Supabase/PostgreSQL — this project deliberately uses
**Firebase Realtime Database** instead (Realtime DB, not Firestore). There is also **no login of any
kind, not even Firebase Anonymous Auth**: `IdentityService` generates a random id once and caches it in
`SharedPreferences`; that id is the only identifier used anywhere in the data model and is never shown to
other users. `database.rules.json` is correspondingly open (`.read: true` / `.write: true` at the root),
with `.validate` rules only checking that required fields are present, not who is writing.

RTDB paths (see `AppConstants`): `communities/{id}`, `communityMembers/{communityId}/{userId}`,
`locationReports/{communityId}/{supplierId}`. Location reports are latest-write-only per supplier — no
movement history is ever stored, by design (see `prompt.md` §15).

### Config placeholders

`lib/firebase_options.dart` and the Google Maps API keys (`android/app/src/main/AndroidManifest.xml`,
`ios/Runner/AppDelegate.swift`) are TODO placeholders. Without a real Firebase project wired in via
`flutterfire configure`, the app builds and runs but RTDB reads/writes fail (caught, non-fatal) and the
map renders blank/grey.

### Localization

All user-facing strings must go through ARB files (`lib/l10n/app_en.arb`, `lib/l10n/app_bn.arb`) and the
generated `AppLocalizations` — no hardcoded UI strings. Bengali translations should read naturally, not
as literal machine translations (see existing ARB entries for tone/phrasing precedent).
